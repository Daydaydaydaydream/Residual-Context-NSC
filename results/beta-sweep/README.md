## 选择规则

按项目计划：对负验证 PPL 的 Spearman ρ 最高者胜出；ρ 并列时先取 |β| 较小者，再优先负号。
本次三组都没有出现 ρ 并列，因此并列规则没有被触发。

| 设置 | 选中 β | Spearman ρ | Kendall τb（全部对） | τb（180 受控配对） |
|---|---:|---:|---:|---:|
| 主方法 | **-100** | 0.972817 | 0.879596 | 0.666667 |
| 共同加权 | **-1** | 0.970153 | 0.863434 | 0.633333 |
| 指数形式 | **-100** | 0.972241 | 0.881616 | 0.600000 |

对照：β = 0 的 ρ 为 0.969745、τb 为 0.861414、受控 τb 为 0.622222，这一行同时也是加性消融
（`ablation` 恒等于 β = 0，见 `scripts/verify_adapter.py`）。

全部 33 组见 [`beta_sweep.md`](beta_sweep.md)，机器可读结果见 [`beta_sweep.csv`](beta_sweep.csv)
与 [`beta_sweep.json`](beta_sweep.json)。

## 读这张表要注意

- **选中的 ρ 是乐观估计**：β 是在同一批开发集上挑的，报告 ρ 时要连同全部 33 组一起给出，不能只报选中值。
- 主方法与指数形式在 β 接近 0 时几乎重合（两者在零点的一阶行为相同），差别体现在大 |β| 的尾部。
- β = -1000 时共同加权的 ρ 掉到 0.883、受控 τb 掉到 0.122，符合权重趋近 0 时的极限行为，不是计算错误。
- 每组只有 100 个架构，ρ 差异在小数点后第三位；这些差距本身不足以支撑"改进"这类结论，只用于选参。
- 本目录只是开发集选参记录，最终集评估要在方法冻结后单独跑。
